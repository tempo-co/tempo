# Production deploys a nightly release

Production deploys each app's `:release` image, not `:main`. A merge tags its tested images as `:main` once the whole CI run passed (`docs/ci-and-images.md`, Release main images), and the `Release` workflow moves `:release` to the newest `:main` every night, forward only, API before web; a manual run of the same workflow releases at once, by the owner or by an agent on the owner's word. Each release costs about 12 seconds of failed requests while API and web restart, and with about six merges a day at any hour that downtime would land while people use the app, so releases wait for the night. The pull request review and its green CI run remain the gate into `main`, so `main` must stay releasable at all times: work that must not reach users yet stays off `main` or behind a deployment switch, as statement file import does with `FILE_IMPORT_ENABLED`. The server pulls on its own every 5 minutes (`ops/README.md`), so GitHub holds no key to it. The nightly run is started by a timer on the server, since GitHub's own schedule is best-effort and can start hours late or skip a night; the server holds a token that can only start workflows in this repository.
