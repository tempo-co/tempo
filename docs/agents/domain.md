# Domain docs

Single context. Before exploring, read root `GLOSSARY.md` if it exists and the ADRs in `docs/adr/` that touch the area. If they don't exist, proceed silently; `/domain-modeling` creates them when a term or decision gets resolved.

Name domain concepts with the glossary's terms, not synonyms it avoids; a concept missing from it is either invented language or a gap to note for `/domain-modeling`.

If your output contradicts an ADR, say so explicitly ("Contradicts ADR-0002, but worth reopening because…") instead of silently overriding it.
