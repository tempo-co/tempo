# Reporting currency

The one currency every combined total is in, and how amounts are converted into it.

- `accounts.baseCurrency` is the owner's reporting currency: every `amountInBaseCurrency` and every combined total is in it. Only `ReportingCurrencyService` (`src/app/modules/banking/services/reporting-currency.service.ts`) sets it; reads and the conversion job never pick one.
- While every active account holds one currency, that one is used (`AUTOMATIC`) as soon as authorization, a sync, an import or a removal shows it, and a currency the owner never chose follows it, also when removing a bank leaves one currency where they were being asked. Once accounts hold several and a sync or import has finished, the owner is asked once (`SETUP_PENDING`), and an automatic currency stays until they answer. Without one, `GET /reporting-currency` suggests the currency of the most booked transactions of the last 90 days, leaving out own transfers and currency exchanges; a tie suggests nothing, and nothing is saved without the owner. A chosen currency (`CONFIRMED`, or `PRESET` for one stored before owners could choose) never changes by itself.
- The choice is EUR or a currency the ECB publishes a daily reference rate for (`REPORTING_CURRENCIES` in `@tempo/contracts`). A stored currency outside that list stays and can be confirmed.
- A change clears every converted amount of the owner and copies the ones already in the new currency, in one transaction. When rows are left to convert it bumps `baseCurrencyRevision`, and totals are ready again once a conversion pass finishes for that revision (`baseAmountsRevision`). Until then every money response carries `baseCurrency: null` (`totalsCurrency`). A pass that leaves rows without a rate still finishes the change; those rows count as `excluded.missingBaseAmount`.
- Every transaction that writes converted amounts (sync and import writes, the conversion job) takes `lockReportingCurrencyForAmountWrites` as its first statement, and a change takes the same lock exclusively, so neither can write in the other's currency. Taken after a transaction has locked transaction rows, it can deadlock with a change. The conversion job also skips an owner whose currency or revision changed after it fetched rates.
- A change queues a conversion pass at once; the 15-minute run and the boot backfill pick up one that was lost. Conversion runs while bank sync or file import is enabled. Tests run neither and call the job themselves.
