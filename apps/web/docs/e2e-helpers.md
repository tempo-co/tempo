# E2E test helpers

The shared helpers of the Playwright suite under `test/`, and the rules for reusing them. Running specs, mocks and traps are in `docs/browser-and-e2e-testing.md`.

## Helpers

- `test/fixtures.ts`: import `test` and `expect` from here instead of `@playwright/test`. It provides the page objects as fixtures (`loginPage`, `homePage`, `signupPage`, `verifyEmailPage`, `verifyEmailChangePage`, `resetPasswordPage`, `accountSettingsPage`, `securitySettingsPage`, `appearanceSettingsPage`), plus:
  - `freshAccount`: a new verified account with no bank data, with the test's browser context logged in as it.
  - `createVerifiedAccount(request)`: the same account without logging in, for tests that log in through the UI.
- `test/data/account.data.ts` (`createAccount`) and `test/data/bank-transaction.data.ts` (`createBankTransaction`) return complete typed HTTP response fixtures. `test/data/recurring.data.ts` builds recurring series and lists the way the API adds them up, with demo and worst-case months. Override the fields the scenario depends on; keep its actions and assertions in the spec.
- `test/utils/api-mocks.ts`: `mockBankConnections`, `transformBankConnections` and `routeBankConnectionsApi` intercept the `GET /bank-connections` API call while letting navigations to the old `/bank-connections` address through. `mockJson` and `fulfillJson` answer other routes with JSON. `mockEmptyHome` answers Home's history requests with empty data (from parts such as `mockEmptyRecurringLists` and `EMPTY_REVIEW_COUNTS`, which specs that replace its routes reuse); fully mocked specs get it, `mockBankConnections(page, [])`, file import off (`mockFileImportOff`) and no push by default from `test/fixtures.ts`. `failLaterPages` fails a paged list's later pages until told to stop, and `expectFailedPageRetried` checks that the loaded rows stay and Retry adds the page.
- `test/utils/accounts.ts`: `mockAccountsApi` answers what Accounts and an account page read (connections, imports, the account's transactions and balance trend) from one changeable source; `balanceTrend` builds a month-end trend. `test/utils/bank-connections.ts`: `routeMockedBankApp` signs in a mocked account and fails any unmocked request; `accountRow`, `attentionLines`, `openAccount` and `openRemoval` find an account's row, its warning freshness lines, its page and its connection's removal. `test/data/bank-import.data.ts`: `bankImport` and `importedFiles` build an import summary and the imported-files connection.
- `test/utils/recurring.ts`: the Recurring page's groups, cards, rows (by key or name) and details. `test/e2e/recurring/recurring-month.spec.ts` runs on the recurring owner seeded by `apps/api/scripts/seed-data/seed-recurring-data.ts`.
- `test/utils/file-import.ts`: `mockFileImport` answers the statement file import's API and keeps its import list in step with uploads, answers and undo; each drop's preview comes first (`api.previews`), answered by a `refused` answer or else described by `previewOf` the summary a `created` answer imports, and `importFound` clicks Check what we found's Import; `importSummary`, `IMPORTED_FILES`, `mockSetBalance`, `sentForm` (an upload's file names and text fields) and the sheet helpers (`openImport` from Accounts, `openImportFromAddData` from any page, both through the bank picker's Another bank via `pickAnotherBank`) serve the import specs and the Accounts imports spec. `test/utils/bank-picker.ts`: `connectThroughPicker` connects a bank through Accounts' Connect a bank.
- `test/utils/layout.ts`: `boxOf(locator)` returns a rendered element's bounding box, `expectNoHorizontalOverflow(page)` checks for horizontal scrolling, `expectLoaded(scope)` waits until no part of it is `aria-busy`, and `brokenAmounts(page)` lists visible amounts that are cut short, overflow or wrap. Home, Insights and the month page show placeholders of the loaded size while sections load, so measure only after `expectLoaded` or a loaded value.
- `test/utils/url.ts`: `withSearchParams(path, params)` builds URLs for the invalid-search-param cases in `test/data`.
- `test/utils/email-utils.ts`: `EmailUtils.getVerificationCode(email)` reads a verification code from Mailpit; `ResetPasswordPage.openResetLink(email)` requests a reset and opens the emailed link.
- `test/utils/hook-harness.ts`: `createHookHarness(stubs)` runs a real hook against a real `QueryClient` with whole modules stubbed (see Hook harness below).
- `test/utils/toasts.ts`: `countAfterToasts(page, locator)` counts matches once, after the toasts already raised have rendered. Use it to assert a message appears exactly once; a retrying `toHaveCount` would wait an extra toast out.

## Reusing fixtures

- Tests that change account data or depend on an account having no bank data use `freshAccount` rather than a seeded account, so they do not depend on test order and stay safe to retry. Do not change seeded data another test reads. The exception is a flow that needs stored bank data the API cannot create: it signs in as an owner seeded for it alone and puts back what it changes, also at the start of a retry (`test/e2e/recurring/recurring-month.spec.ts`).
- Password changes and session revocation must not invalidate an identity another test or browser project reuses. Request `freshAccount` in the setup hook before navigating.
- Keep meaningful dates, amounts, category states, conversion evidence and linked identities explicit in the spec, not in fixture defaults. Use local helpers for repetition within one spec and shared helpers only for a contract multiple specs need.
- Do not cast incomplete responses to a contract type or share a mutable fixture between tests. Do not use API entity factories or full database seeds to construct HTTP mocks: they represent different boundaries.
- Write repeated validation cases as a `for` loop over a table of cases.

## Hook harness

`createHookHarness` is for cache behaviour the UI cannot set up. A named import missing from a stub is `undefined` in the harness, so the failure-path test throws `TypeError` instead of the expected error. Add every named import a hook uses from a stubbed module to the stubs; for `@/utils/api` or `sonner` add it to every stub of that module (for example `isAuthError: () => false`, `toast.error: () => undefined`). Current users: `grep -rl createHookHarness test`.
